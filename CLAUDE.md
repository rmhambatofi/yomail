## What this is

`yomail` is a webhook catcher (webhook.site-like) for `yo.manitra.fr`. A user creates an endpoint (server-generated UUID v4) and sends any HTTP request to `https://yo.manitra.fr/<uuid>[/sub/path]`; requests show up live at `/inbox/<uuid>`. No auth: knowing the UUID is the only key, and anyone who knows it can read, clear or delete the endpoint. Hosted on shared cPanel (no root), Node 22, MySQL, app served by Passenger. UI in English. v1 explicitly excludes configurable responses, search, replay, export, notes, geo-IP, auth, rate limiting, tests, CI.

## Architecture

Request path, end to end:

1. Apache + Passenger (cPanel) mount the Nest app at the **root** of the subdomain (Phase 6; v1 mounted it at `/api`).
2. NestJS API (`apps/api`): `CaptureController` (`@All('/:uuid')`, `@All('/:uuid/*')`, excluded from the `/api` prefix) checks the endpoint exists, streams the body with a size limit (`capture/raw-body.ts`), classifies it (`content_kind`: none/json/form/multipart/html/xml/text/binary), stores one `requests` row and answers `200 {"ok":true,"id"}` with CORS `*`. `EndpointsController` / `RequestsController` serve `/api/endpoints/...`. `LiveGateway` (Socket.IO on `/api/socket.io`) pushes `request:new` to rooms `ep:<id>`. `PurgeService` deletes expired requests and idle endpoints. `ServeStaticModule` serves `apps/web/dist` for everything else when `WEB_DIST_DIR` is set.
3. React SPA (`apps/web`): `/` (create / open / recent endpoints), `/inbox/:uuid` and `/inbox/:uuid/:rid` (one `InboxPage`: request list + `RequestPanel` with details, headers, query params, content viewers). `lib/useLiveRequests.ts` uses Socket.IO and falls back to REST polling (5 s) when the socket is down.

Why no WebSocket in production: Passenger on Apache does not support the WebSocket upgrade, so Socket.IO runs over HTTP long-polling there. Passenger may also run several app processes, so the gateway polls the DB every 2 s for subscribed endpoints in addition to in-memory events, and clients dedupe by id.

### Monorepo layout (npm workspaces; pnpm is not available on cPanel)

- `packages/shared` — DTOs (`EndpointSummary`, `EndpointDetail`, `RequestSummary`, `RequestDetail`, `RequestListResponse`, `CaptureResponse`, `HealthStatus`, Socket.IO event maps) plus `ENDPOINT_ID_REGEX`, `extractEndpointId()` (UUID or full URL → lowercase id), `shortEndpointId()`, `shortRequestId()`. **Single source of truth** for the endpoint id rule used by both API and web. Ships dual ESM (`index.js`) + CJS (`index.cjs`) because Nest compiles to CommonJS and Vite consumes ESM.
- `apps/api` — NestJS 10 + TypeORM + MySQL. Modules: `config`, `database` (datasource + migrations), `settings`, `health`, `purge`, and (per plan) `endpoints`, `requests`, `capture`, `live`, `static`. `capture/raw-body.ts` (streaming body reader with 413) and `requests/html-sanitizer.ts` (`sanitizeHtmlBody`) are kept from v1. `src/cli/purge.ts` (compiled to `dist/cli/purge.js`, **not** `bin/`: a second root dir would shift `dist/main.js`) is the CLI entry used by the cPanel cron; it boots its own `PurgeCliModule` with `createApplicationContext`, so no HTTP server and no in-process scheduler.
- `apps/web` — React 18 + Vite + TS + Tailwind + React Router (+ `socket.io-client` from Phase 4). No global state manager: `lib/useAsync.ts` (fetch on mount, abort on unmount, `reload()`) plus `useState`. `api/client.ts` is the only place that calls `fetch`; it throws `ApiError` with the HTTP status so pages can special-case 400/404. `components/HtmlFrame.tsx` builds the iframe `srcdoc` (CSP meta, base CSS, `data-src` → `src` swap when "Load images" is on). `config.ts` exposes `API_URL` (`/api`) and `PUBLIC_BASE_URL` (`window.location.origin`: SPA and capture routes share one origin).

### Key invariants

- **Retention is computed, never stored.** `expires_at = received_at + settings.retention_days`, calculated at read and purge time. Changing `retention_days` in the `settings` table (default `10`) applies immediately. An endpoint is idle (and purged) when `COALESCE(last_request_at, created_at) < cutoff`.
- **Capture rules**: validate the UUID by regex before anything else; check the endpoint exists **before reading any body byte** (404 otherwise); `413` above `MAX_BODY_BYTES` and nothing stored; at most `MAX_REQUESTS_PER_ENDPOINT` (500) rows per endpoint, oldest dropped on insert; always answer with CORS `*`; `HEAD` → 200 without body; `OPTIONS` is captured like any other method.
- **Bodies are untrusted text.** Files and binary bodies are never stored (multipart file parts are counted into `dropped_files` and discarded; binary content types keep metadata only). HTML is sanitized **on read** (`html_sanitized` is never stored) and rendered client-side only inside `<iframe sandbox="allow-popups allow-popups-to-escape-sandbox" srcdoc=...>` with an injected CSP meta. **Never add `allow-same-origin`**; use a fixed scrollable height. Never use `dangerouslySetInnerHTML` outside the iframe. JSON is pretty-printed as text.
- Ids go through `ParseUUIDPipe` → 400 if malformed. A request `id` that exists but belongs to a different endpoint → 404, for reads and deletes alike (the service always filters on `{ id, endpointId }`).
- **List queries never load `body`, `headers`, `form_fields`**: use explicit `select` column lists (`SUMMARY_COLUMNS`, `DETAIL_COLUMNS`). Lists are newest first, 50 per page (max 200), cursor `?before=<received_at>`. Deletes return 204 with no body.
- TypeORM runs with `synchronize: false`; every schema change is a migration in `apps/api/src/database/migrations`, listed explicitly in `migrations/index.ts` (no glob, so ts-node and dist share one list). `buildDataSourceOptions()` in `data-source.ts` is shared by the Nest module and the CLI. Entities use snake_case column names explicitly (`name:`), camelCase properties. JSON columns use `type: 'json'` (works on MySQL 8 and MariaDB). The FK is named explicitly (`foreignKeyConstraintName: 'fk_requests_endpoint'`) and indexes are ascending with explicit names, so `migration:generate` sees no diff; keep it that way (TypeORM compares FKs by name and does not model DESC indexes).
- API prefix `/api` (`API_PREFIX`, empty = no prefix; `main.ts` skips `setGlobalPrefix` when empty), all responses `Cache-Control: no-store`. CORS on `/api`: same origin in prod, `http://localhost:5173` in dev, applied with the `cors` middleware **only outside capture paths** (`isCapturePath`): the middleware would otherwise answer `OPTIONS` preflights itself and the capture route would never see them. The API boots with `bodyParser: false`; routes needing JSON must opt in per route. `TRUST_PROXY=1` in prod so `req.ip` reflects `X-Forwarded-For`.
- **Global prefix exclusion gotcha**: `setGlobalPrefix(prefix, { exclude })` tests each exclude pattern (path-to-regexp 3) against the _literal route strings_, not incoming URLs. A pattern like `:id` matches `/health` too and silently strips the prefix from every single-segment route. `capture/routes.ts` therefore excludes the escaped literal route strings (`\:endpointId\(...\)`); check the `Mapped {...}` boot log after touching this. The capture controller writes its responses by hand (`@Res()`), so 404/413 also carry CORS `*` and the `{ ok, id | error }` body.
- Purge has two triggers: hourly cPanel cron running `npm run purge` (source of truth) and an `@nestjs/schedule` hourly job in `PurgeScheduleModule` as backup. `PurgeService.run()` invalidates the settings cache, computes the cutoff in JS, deletes requests with raw `DELETE ... ORDER BY received_at LIMIT 1000` in a loop (TypeORM's `delete()` has no LIMIT), then idle endpoints. A re-entrancy flag skips overlapping runs. `--dry-run` counts only, `--quiet` logs errors only.
- In `apps/api`, classes injected through constructors must stay runtime imports (not `import type`), or Nest DI breaks; the `consistent-type-imports` lint rule is disabled for that app on purpose.
- **Server config lives only in `apps/api/.env`** on cPanel, never in the Passenger UI: the cron and migrations run outside Passenger and would not see UI variables. `npm ci --omit=dev` must run at the monorepo root on the server (workspace link to `@yomail/shared`), not from cPanel's _Run NPM Install_ button.
- Live updates must keep working without WebSocket and across several Passenger processes (DB polling in the gateway, dedupe by id on the client, REST polling fallback). Do not write code that assumes a single process or a real WebSocket.

## Commands

- `npm install` at root
- `npm run dev` — API on 3000 + web on 5173 (Vite proxies `/api` with `ws: true` and `/<uuid>...` capture paths → `localhost:3000`; set `VITE_PROXY_TARGET=http://localhost:3010` to point the proxy elsewhere)
- `npm run build` — shared, then api, then web (`packages/shared` must build first; api and web consume its `dist`)
- `npm run lint` / `npm run format` / `npm run typecheck` — root ESLint 9 flat config (`eslint.config.mjs`), Prettier, per-workspace tsc
- `npm run build -w apps/api` / `-w apps/web`
- `npm run migration:run|revert|show -w apps/api` — TypeORM CLI via ts-node on `src/database/data-source.ts`; `migration:run:prod` uses compiled `dist/` for cPanel
- `npm run migration:generate -w apps/api -- src/database/migrations/<Name>` — diff entities vs DB; then **add the class to `src/database/migrations/index.ts`**
- `npm run purge` (alias of `-w apps/api`), `npm run purge:dry-run -w apps/api`, `npm run purge:dev -w apps/api` (ts-node, no build)
- `CPANEL_SSH=user@host npm run deploy [-- --dry-run|--skip-build|--no-migrate]` — build + tar-over-ssh upload (including `apps/web/dist`) + remote `npm ci`, migrations, `.htaccess` merge, Passenger restart.
